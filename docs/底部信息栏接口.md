# 底部信息栏接入指南

[← 返回 README](../README.md)

其他 SPW 插件可向 AMLL into SPW 的底部信息栏提交当前歌曲的 key/value 数据，例如匹配来源、歌曲标识、翻译作者或版权说明。接口独立于原始 TTML 互通，使用本地 TTML、宿主歌词或没有可用歌词时均可提交，纯音乐页面也支持显示。

发送方使用 Workshop API 的 `getCurrentMediaItem()` 获取当前歌曲身份时，需要在插件清单声明 `library-read`（Gradle 中的 `PluginPermission.LIBRARY_READ`），并在 SPW 中获得「读取曲库」授权。缺少授权会抛出 `PluginPermissionDeniedException`；启用时应检查权限并明确报告，不能将异常静默当作「没有当前歌曲」。

歌词页面先显示 AMLL 自身的元数据与歌词来源，再显示其他插件的信息；纯音乐页面只显示其他插件的信息。各插件按名称排序，每组字段保留提交顺序，并由 AMLL 标注 `From: 名称`。

例如：

```text
歌名：示例歌曲
歌词来源：歌曲同名 TTML 文件
From: AMLL into SPW

匹配来源：示例曲库
歌曲 ID：12345
From: Alpha Lyrics

翻译作者：示例作者
From: 歌词助手
```

调用方只提供身份与 key/value，样式和布局由 AMLL 处理；HTML、Markdown 等内容按普通文字显示，外部信息不会覆盖 AMLL 自身的信息。

用户可在插件设置中开启“隐藏底栏信息”，统一隐藏 AMLL 自身及其他插件的底栏内容，适用于普通歌词、无歌词与纯音乐页面；该开关默认关闭。隐藏仅影响显示，接口仍照常接收、更新和撤回数据，关闭开关后显示当前信息。

## 协议 1

接口通过 JVM 平台 MBeanServer 跨插件类加载器调用，只使用 JDK 类型，无需依赖本插件 JAR，不开启端口或网络服务。接收器随 AMLL into SPW 启用而注册，停用时注销并清空数据。

ObjectName：`io.github.gaboron.amllspw:type=FooterReceiver,version=1`

| 属性或操作 | 含义 |
| --- | --- |
| `ProtocolVersion` | 只读 `int`，当前为 `1` |
| `Active` | 只读 `boolean`，插件是否启用且具备必要权限 |
| `submitFooter(String providerId, String providerName, String trackId, String audioPath, String[] keys, String[] values)` | 返回 `boolean`；整体替换该插件在当前歌曲下的信息 |
| `clearFooter(String providerId, String trackId, String audioPath)` | 返回 `boolean`；撤回该插件在当前歌曲下的信息 |

参数约定：

- `providerId` 使用发送插件稳定、唯一的插件 ID，区分大小写。长度 1–128，首字符为英文字母或数字，其余允许英文字母、数字、`.`、`_`、`-`。相同 ID 的新提交替换旧提交；名称可随提交更新。
- `providerName` 由调用方声明，用于排序及 AMLL 生成的 `From: …`。必须为非空单行文本，最长 128 个字符，不允许换行或制表符；首尾空白会去除。
- `trackId` 使用 Workshop API 的 `MediaItem.id`，没有 ID 时传空字符串；`audioPath` 必须使用 `MediaItem.path`。两端 ID 均非空时，ID 与规范化路径必须同时匹配，Windows 路径不区分大小写。只接受当前歌曲。
- `keys` 与 `values` 必须等长，每个索引组成一条信息。允许 1–64 条；key 为非空单行文本，最长 128 个字符，不允许换行或制表符；value 为非空文本，允许换行，最长 4,096 个字符。每组所有 key/value 总长度不超过 32,768 个字符。长度按 JVM `String.length` 计算，首尾空白在校验后去除。
- 最多同时保留 16 个插件的信息。达到上限后，已有 ID 仍可替换；新 ID 需等待其他插件撤回。参数与数组元素均不能为 `null`。

`submitFooter` 返回 `true` 表示数据已接收，随后由后台队列更新显示；`false` 表示歌曲不匹配、参数无效、超限或接收器不可用，既有有效信息保持不变。同一 ID 不做字段合并，移除字段时直接重新提交剩余字段。空数组会被拒绝；清空整组请调用 `clearFooter`。撤回返回 `false` 也可能只是该插件没有可撤回的数据。

## Java 调用模板

下面的客户端只依赖 JDK。应在后台线程调用，每次操作重新检查接收器，以兼容双方独立启停。字符串数组的 JMX 签名必须为 `[Ljava.lang.String;`，可直接使用 `String[].class.getName()`。

```java
import java.lang.management.ManagementFactory;
import javax.management.ObjectName;

public final class FooterClient {
    public static boolean submit(String providerId, String providerName,
                                 String trackId, String path,
                                 String[] keys, String[] values) {
        return invoke("submitFooter",
                new Object[]{providerId, providerName, trackId, path, keys, values},
                new String[]{"java.lang.String", "java.lang.String",
                        "java.lang.String", "java.lang.String",
                        String[].class.getName(), String[].class.getName()});
    }

    public static boolean clear(String providerId, String trackId, String path) {
        return invoke("clearFooter", new Object[]{providerId, trackId, path},
                new String[]{"java.lang.String", "java.lang.String", "java.lang.String"});
    }

    private static boolean invoke(String operation, Object[] arguments, String[] signature) {
        try {
            var server = ManagementFactory.getPlatformMBeanServer();
            var target = new ObjectName("io.github.gaboron.amllspw:type=FooterReceiver,version=1");
            if (!server.isRegistered(target)
                    || !Integer.valueOf(1).equals(server.getAttribute(target, "ProtocolVersion"))
                    || !Boolean.TRUE.equals(server.getAttribute(target, "Active"))) return false;
            return Boolean.TRUE.equals(server.invoke(target, operation, arguments, signature));
        } catch (Exception unavailable) {
            return false;
        }
    }
}
```

发送示例，其中 `media` 是当前歌曲的 Workshop `MediaItem`：

```java
FooterClient.submit("org.example.lyrics", "示例歌词插件", media.getId(), media.getPath(),
        new String[]{"匹配来源", "歌曲 ID"},
        new String[]{"示例曲库", "12345"});

// 撤回时使用同一个插件 ID 和歌曲身份。
FooterClient.clear("org.example.lyrics", media.getId(), media.getPath());
```

## 更新与生命周期

1. 获取结果时保留歌曲 ID、路径与发送端自己的选择版本；提交前核对仍是当前选择，忽略迟到任务。将提交、撤回和重试放在同一后台队列，避免旧操作覆盖同一首歌的新选择。
2. 每次提交都是完整快照。名称、字段或取值变化后重新提交，无需重发 TTML。数据只存在于内存，切换歌曲或停止播放并清空当前歌曲后清除；重新播放同一首歌时应重新提交。
3. AMLL 后启用或停用后重新启用时，发送端重新检测并提交当前快照。可以监听 `MBeanServerDelegate` 的注册/注销通知，或定期检测；不要永久缓存接收器存在状态。
4. 发送插件停用、撤销当前选择或不再提供信息时，主动调用 `clearFooter`。停止后台任务、移除监听器；AMLL 自身停用时会统一清空。信息没有自动过期计时，发送插件应负责主动撤回。
5. 本接口与 [原始 TTML 接口](TTML互通.md) 各自更新、各自撤回。清除 TTML 不会清除信息，清除信息也不影响歌词；歌词发送端继续保留自己的宿主歌词输出流程。
