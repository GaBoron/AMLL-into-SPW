# 插件兼容性评估

> 更新日期：2026-10-19  
> 评估对象：AMLL into SPW 0.3.0 与 GitHub [salt-player-plugins Topic](https://github.com/topics/salt-player-plugins) 中的其他插件。  
> 评估方式：查阅公开 README、接口文档及部分关键源码。**本页是静态兼容性评估，不是组合安装后的实测结果。**

## 范围与结论

截至本次整理，该 Topic 共列出 22 个仓库，包括 AMLL into SPW 自身；下表覆盖其余 **21 个插件**。Topic 列表会变化，后续新增项目不自动包含在本文中。

AMLL into SPW 需要 **SPW 1.19.0 / Workshop API 0.1.0-dev23**，使用 `replaceComposable` 接管原生播放页的歌词组件，并读取当前播放状态。它不会接管整张播放页面或其他插件的独立窗口。

因此，“两个插件都能显示歌词”不等于互相冲突。更值得注意的交互点是：

- **界面 Hook**：是否替换同一个宿主调用位置；不同组件也可能在宿主升级后分别失效。
- **歌词来源**：多个插件通过 `onBeforeLoadLyrics`、`updateLyrics` 等回调提供文本时，最终采用哪一份取决于宿主的加载逻辑；不能把它们的输出视作自动合并。
- **原始 TTML**：AMLL 优先使用本地 TTML，其次接收原始 TTML 接口，再回退至 SPW 已解析的歌词时间轴；仅修改宿主 SPL/LRC 的插件不一定能影响优先级更高的 TTML 显示。
- **显示范围**：桌面歌词浮窗和其他全屏可视化通常读取宿主歌词；即使与 AMLL 同时工作，也未必具有 AMLL 解析的对唱、背景人声等原始 TTML 信息。

### 状态说明

- **已实现互通**：双方代码已经提供明确的交互协议；不等于在所有版本、场景下完成联合实测。
- **预期可共存**：按当前文档及实现，主要作用于不同功能或界面；仍需以实际安装验证。
- **需重点验证**：存在歌词来源竞争、宿主 Hook 或版本敏感等具体交互点。

## 值得优先验证的组合

1. **AMLL + SPW Lyrics**：覆盖同名/内嵌 TTML、在线原始 TTML、普通 SPL/LRC 回退；双向启停、先后安装、切歌、进度跳转与歌词延迟。
2. **AMLL + 多个歌词来源插件**：分别启用及组合启用 SPW Lyrics、网易云插件、双语歌词插件和 FLAC 时间标记修复插件。观察宿主最终使用哪个来源，确认未出现空歌词、旧曲歌词残留或加载停滞。
3. **AMLL + SPW-Animated-Album-Art**：同时进入/退出原生播放页，检查歌词与封面是否均能绘制；分别停用和重新启用两个 Hook，确认无界面残留、异常或崩溃。
4. **AMLL + 桌面歌词插件 / Folia**：检查原生页与独立窗口能否同时显示、暂停与跳转是否同步。对于仅有原始 TTML 的歌曲，单独核对各窗口的歌词内容，不将显示差异误认为 Hook 冲突。
5. **AMLL + 标签编辑工具**：在外部工具保存歌词或封面变更后重新选曲，核对 AMLL 读到的是旧内容还是新内容。
6. **生命周期与版本**：重点记录 SPW 与 Workshop API 版本、插件版本、权限、加载顺序、宿主日志；组合启停后再测试普通歌词回退，防止把“插件本身不支持当前 SPW”误记为“插件之间冲突”。

## 出现问题时如何判断

- **只有 AMLL 歌词不显示**：先单独启用 AMLL，检查宿主版本、权限与原生歌词 Hook 是否成功；再考虑其他 UI Hook。
- **AMLL 与宿主或桌面浮窗显示不同**：先对比歌曲是否存在原始 TTML，以及 AMLL 是否使用本地/跨插件 TTML；不同显示端的数据来源可能不同。
- **歌词来源不符合预期**：只保留一个歌词提供插件，逐一增加，观察加载结果；不要仅凭插件安装顺序推断回调优先级。
- **切歌后歌词错位或残留**：记录歌曲 ID、文件路径、播放状态以及是否刚刚修改标签或调整队列。
- **禁用插件后仍有问题**：完全退出并重启 SPW 再验证，区分宿主缓存、运行中的 Hook 与歌词文件本身的问题。
